# User scenarios

## US-01. Просмотр списка заведений

### Цель
Пользователь хочет выбрать заведение для оформления заказа.

### Предусловия
- В системе существуют активные заведения.

### Основной сценарий
1. Пользователь открывает Авито.Кухню.
2. Клиент запрашивает список заведений.
3. Система возвращает доступные заведения.
4. Пользователь выбирает одно из заведений.

### Результат
Пользователь может перейти к просмотру меню выбранного заведения.

---

## US-02. Просмотр меню заведения

### Цель
Пользователь хочет увидеть позиции выбранного заведения.

### Предусловия
- Заведение существует.

### Основной сценарий
1. Пользователь выбирает заведение.
2. Клиент запрашивает меню.
3. Система возвращает позиции меню.
4. Для каждой позиции отображаются:
   - название;
   - описание;
   - цена;
   - доступность.

### Альтернативный сценарий
Если заведение не существует, система возвращает ошибку.

---

## US-03. Создание заказа

### Цель
Пользователь хочет оформить выбранные позиции.

### Предусловия
- Заведение существует.
- Все позиции принадлежат выбранному заведению.
- Позиции доступны для заказа.
- Количество каждой позиции больше 0.

### Основной сценарий
1. Пользователь выбирает позиции.
2. Пользователь отправляет запрос на создание заказа.
3. Система проверяет существование позиций.
4. Система проверяет их принадлежность заведению.
5. Система проверяет доступность.
6. Система получает актуальные цены и названия.
7. Система рассчитывает итоговую стоимость.
8. Система создаёт заказ со статусом CREATED.
9. Система сохраняет snapshot данных позиций в OrderItem.
10. Система возвращает созданный заказ.

### Результат
Заказ создан и доступен заведению.

### Ошибочные сценарии
- Заведение не существует.
- Позиция не существует.
- Позиция относится к другому заведению.
- Позиция недоступна.
- quantity <= 0.

---

## US-04. Попытка заказать недоступную позицию

### Сценарий
1. Пользователь получает меню.
2. Позиция в этот момент доступна.
3. Заведение делает позицию недоступной.
4. Пользователь пытается создать заказ.
5. Система повторно проверяет доступность.
6. Заказ не создаётся.

### Результат
Пользователь получает бизнес-ошибку о недоступной позиции.

---

## US-05. Просмотр заказа

### Цель
Пользователь хочет узнать состояние своего заказа.

### Основной сценарий
1. Пользователь запрашивает заказ по ID.
2. Система возвращает:
   - статус;
   - ресторан;
   - итоговую стоимость;
   - позиции заказа.

### Важное правило
Название и цена OrderItem берутся из snapshot, сохранённого при создании заказа,
а не из текущего MenuItem.

---

## US-06. Отслеживание статуса заказа

Пользователь периодически получает состояние заказа.

Допустимый успешный жизненный цикл:

CREATED -> ACCEPTED -> PREPARING -> READY -> COMPLETED

Возможен отказ:

CREATED -> REJECTED
